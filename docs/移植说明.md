# 移植说明（Android → iOS）

本文记录 `app/src/main/jni` 那套 Android 原生菜单是**怎么一步步变成** `ios/SawitMod` 的：
哪些代码原样搬、哪些必须换实现、哪些只能到 iOS 包上重新标定。

---

## 1. 两个平台的结构差异

| 能力 | Android 版 | iOS 版 |
|---|---|---|
| 加载方式 | `System.loadLibrary("SawitMod")` → `JNI_OnLoad` | 注入 dylib，`__attribute__((constructor))` |
| 菜单窗口 | Java `SurfaceView` + WindowManager 悬浮窗 | `UIWindow`（level=Alert+100）+ `CAEAGLLayer` |
| 画菜单 | hook `eglSwapBuffers`，在 Unity 的 GL 上下文里画 | 自己的 `EAGLContext` + `CADisplayLink`，独立 framebuffer |
| 触摸 | hook `libinput` 的 `MotionEvent::copyFrom` | 窗口 `hitTest` 穿透 + `touchesBegan/Moved/Ended` |
| 游戏运行时 | libil2cpp.so（引擎）+ libmonosgen-2.0.so（热更 Mono 程序集） | UnityFramework/主二进制，**纯 il2cpp** |
| 反射 | `mono_*` 经 xdl 从 libmonosgen 解析 | `il2cpp_*` 经 dlsym 解析；`mono_*` 由兼容层映射过去 |
| Hook | Dobby（arm64）/ CydiaSubstrate（armv7） | Dobby（arm64/arm64e） |
| 加密 | `xdl_open("libcrypto.so")` + BoringSSL | 纯 C++ 原语 + Security.framework（ECDH/ECDSA） |
| 网络 | `HttpURLConnection` / raw socket | `NSURLSession`（授权）/ raw socket（微验卡密） |
| 持久化 | `SharedPreferences` | `NSUserDefaults` |
| 设备码 | `Settings.Secure.ANDROID_ID` | Keychain 持久 UUID（回落 `identifierForVendor`） |
| 保存路径 | `/data/data/<pkg>/files/...`、`/sdcard/...` | `Library/Application Support/SawitMod`、`Documents/...` |
| 崩溃日志 | `Thread.setDefaultUncaughtExceptionHandler` | `NSSetUncaughtExceptionHandler` + 信号处理器 |

**为什么不能直接编译**：Java 层（Activity/Service/AlertDialog/Toast/WindowManager）在 iOS 没有对应物，
JNI 头、EGL/ANativeWindow、`/proc`、`libcrypto.so`、`libmonosgen-2.0.so` 也都不存在。
但**业务代码（功能、卡密、云下发、反射、界面）是平台无关 C++**，所以移植策略是：
换掉薄薄的一层平台壳，业务逻辑尽量一行不改。

## 3. 关键改造点

### 3.1 渲染：不再 hook 游戏

Android 版把菜单画进游戏的 EGL surface，靠 hook `eglSwapBuffers` 每帧插入绘制。
iOS 版自建窗口：

```
UIWindow(level=Alert+100, 透明)
└── SMGLView (CAEAGLLayer, ES3)
    ├── EAGLContext + FBO/RBO
    ├── CADisplayLink 60fps → ImGui_ImplOpenGL3_NewFrame → DrawMenu → Render
    └── touchesBegan/Moved/Ended → ImGui io.AddMouse*
```

好处：不碰 Unity 的 GL 状态；Unity 用 Metal 也能用；后台自动暂停。
代价：多一个上下文（显存开销可忽略），且**菜单坐标即屏幕像素坐标**，不需要 Android 那套
`DisplayMetrics ↔ EGL surface` 的换算。

### 3.2 触摸穿透

`OverlayWindow.mm` 的 `SMOverlayWindow hitTest` 在"点不在菜单矩形内"时返回 `nil`，
UIKit 会把这一下继续派发给下面的游戏窗口。菜单矩形来自 `DrawMenu()` 每帧写入的
`g_MenuRect` / `g_MinRect`（与 Android 版同一套结构），所以菜单拖动/最小化后命中区自动跟随。

### 3.3 mono → il2cpp 兼容层

Android 版操作游戏类靠 `mono_class_from_name` / `mono_runtime_invoke`（游戏逻辑是进程内 Mono 程序集）。
iOS 是纯 il2cpp，但**同一个游戏同版本的类名、命名空间、方法名、字段名是一致的**，因此
`IL2CPP/MonoCompat.cpp` 把 35 个 `_monoXxx` 指针逐一映射到 il2cpp 等价 API：

```
mono_get_root_domain      → il2cpp_domain_get
mono_image_loaded         → 按名在 il2cpp domain 的 assembly 里找 image
mono_class_from_name      → il2cpp_class_from_name
mono_class_get_method_from_name → il2cpp_class_get_method_from_name
mono_runtime_invoke       → il2cpp_runtime_invoke
mono_field_*              → il2cpp_field_*
mono_class_get_methods/fields → il2cpp 同名迭代器
mono_gchandle_*           → il2cpp_gchandle_*
mono_compile_method       → 读 MethodInfo 首个字段（il2cpp 全版本一致）
```

**没有等价能力**的（泛型膨胀 `mono_metadata_get_generic_inst`、`mono_assembly_open`、
`mono_class_vtable`）返回空值，调用点会走降级分支 —— 这类功能必须按 il2cpp 重写，
不能靠垫片硬撑。

### 3.4 加密

| Android（BoringSSL） | iOS |
|---|---|
| `SHA256` / `HMAC(EVP_sha256())` | `SMCrypto::Sha256Raw` / `HmacSha256Raw`（纯 C++，带 NIST/RFC 测试向量） |
| `EC_KEY_new_by_curve_name` + `ECDH_compute_key` | `SecKeyCreateRandomKey` + `SecKeyCopyKeyExchangeResult` |
| `ECDSA_do_verify`（r‖s） | `SecKeyVerifySignature`（r‖s 自动转 DER） |
| `EVP_aes_256_gcm` | `SMCrypto::Aes256GcmDecrypt`（纯 C++，CAVP 向量验证） |
| `MD5` / `RC4`（微验卡密） | `SMCrypto::Md5Hex` / `Rc4` |

HKDF 的 salt/info、AES-GCM 的 IV/tag 长度、ECDSA 的绑定串全部与 Android 逐字节一致，
服务端不需要任何改动。

### 3.5 授权与卡密

- `NetAuth.cpp`：会话校验、心跳、`Virbox_*` 入口、catalog 应用都保留；只有
  `GetHWIDNative` / `HmacSha256HexNative` / `HttpPostNative` / `QuitApp` 四个函数换了实现。
- `Weiyan.cpp`：卡密登录协议（RC4 + MD5 签名 + 阿里 DNS 兜底 + chunked 读取）完全保留；
  只把设备码从 `/proc` 指纹换成 `SMPlatform::DeviceCode()`。
- 请求体里的 `"platform":"android"` 有意保留：服务端按这个字段发同一套签名与 payload；
  改成 `"ios"` 需要服务端配合（代码里是两行）。

### 3.6 存储与路径

| 用途 | Android | iOS |
|---|---|---|
| 授权文件 | `/data/data/<pkg>/files/license.txt` | `Library/Application Support/SawitMod/license.txt` |
| 存档点 | `.../files/savepoint.txt` | `.../savepoints.txt` |
| 卡密/设备码 | `.../files/weiyan_*.txt` | `.../weiyan_*.txt`（同目录） |
| 自动绘画素材 | `/storage/emulated/0/Android/data/<pkg>/files/Drawings/` | `Documents/Drawings/` |
| 乐器 / 图片素材 | 同上 `Instrument/`、`Photos/` | `Documents/Instrument/`、`Documents/Photos/` |
| 崩溃日志 | `/storage/emulated/0/Documents/mod_menu_crash_*.txt` | `Documents/mod_menu_crash_*.txt` |

把素材放进 App 的 Documents 有三种办法：iTunes 文件共享、`UIFileSharingEnabled`、
或用 Filza（越狱）。`Info.plist` 需要：

```xml
<key>UIFileSharingEnabled</key><true/>
<key>LSSupportsOpeningDocumentsInPlace</key><true/>
```

### 3.7 启动编排

`App/Bootstrap.mm` 对应 Android 的 `hack_thread`：

1. 装崩溃处理（`SMCrash::Install`）
2. 1.5 秒后在主线程创建悬浮窗口（菜单立即可用，不依赖游戏）
3. `LoadLicenseLocally()`；离线构建再 `LoginOfflineSession` + `LocalCatalog::InstallEmbedded`
4. 轮询等 il2cpp：`il2cpp_domain_get` 等符号可解析 + 主程序集出现（最多 120 秒）
5. `SMMono::InstallPointers()`（把垫片写进 35 个 `_monoXxx`）
6. 若 `OFF_GAMEAPP_UPDATE != 0`：DobbyHook 到 `SMGameAppUpdate`，置 `g_unityFramePumpReady`
7. `ClientControlAgent::InitializeAfterMono()`

## 4. 必须重新标定的东西（`Core/Offsets-iOS.h`）

文件里所有 `0x0` 都是"未标定"哨兵。Android 的 RVA 不能复用（两份不同的编译产物）。

| 需要标定 | 用途 | 找不到时的表现 |
|---|---|---|
| `OFF_GAMEAPP_UPDATE` | 帧泵 hook（任务队列、自动采集、雷达扫描的每帧驱动） | 菜单能开，但"持续运行"类功能不工作（日志：`OFF_GAMEAPP_UPDATE 未标定`） |
| `OFF_THEMIS_P*` / `OFF_SDK_P*` | 反作弊/埋点桩（返回 RET） | 不补也能玩，部分检测可能触发 |
| `OFF_OVERLAP_*` | no-clip / 建筑限制补丁 | 对应功能无效 |
| `OFF_XDPERF_*` | 性能埋点旁路 | 无影响，只是埋点继续上报 |
| `MONO_FIELD_HEADER` / `OFF_ARR_*` / `SZ_DICT_ENTRY` | 反射读数组/字典/值类型 | il2cpp 布局与 Mono 基本一致，但换 Unity 大版本要复核 |

标定步骤：

1. 从**已解密**的 iOS 包里取 `UnityFramework`（或主可执行文件）与 `global-metadata.dat`。
2. IDA/Ghidra 打开，用类名/方法名（`GameApp.Update`、`Themis` 桩等）定位函数。
3. 记录相对 `__TEXT` 的偏移（`函数地址 - 镜像基址`），填回 `Offsets-iOS.h`。
4. 编译后用 `SM_ENABLE_LOG=1` 看启动日志，确认 `GameApp.Update hook ok`。
5. 逐项点亮功能，观察崩溃日志（`Documents/mod_menu_crash_*.txt`）。

> 反射类功能（云端下发的 96 个功能）不需要 RVA：它们按"程序集/命名空间/类/方法签名"
> 走 il2cpp 反射。但**类名/方法名必须与 iOS 版本一致**，且字段偏移要按 iOS 的
> `global-metadata.dat` 复核。

## 5. 已知限制

1. **ObjC++ 部分没有在本机编译过**：Windows 上只能验证纯 C++ 部分（见第 6 节），
   `.mm` 需要在 macOS + Theos 里编一次。常见首编问题：
   - 缺 framework（`UIKit/Foundation/Security/QuartzCore/OpenGLES` 已写进 Makefile）
   - Dobby 的 `libdobby.a` 架构不匹配（要 arm64）
   - 注入后未重签 → 启动闪退
2. **Android 的 Themis/SDK 补丁默认不生效**（RVA=0）：需要标定后才挂。
3. **反调试**：`NetAuth.cpp` 里的 `AntiAnalysisSecurityCheck` 仍读 `/proc`，iOS 上文件不存在，
   等于"未发现篡改"（不崩，但也没防护）。要真正反调试可以接 `SMPlatform::IsDebuggerAttached()`。
4. **Mono 专属能力**：泛型膨胀、`mono_assembly_open`、`GetComponent` 泛型调用在 il2cpp 上要么
   返回空、要么需要改写。相关功能（部分表情/动作解锁）需要按 il2cpp 重写。
5. **卡密面板**：微验的老接口走明文 HTTP（80 端口）的裸 socket —— iOS 的 ATS 不限制裸 socket，
   所以能用，但网络层没有 TLS。
6. **图片/乐器素材**：iOS 沙盒没有 `/sdcard`，需要用户把文件放进 App 的 Documents（见 3.6）。

## 6. 本机验证（Windows 上能做的部分）

`ios/scripts/check_link.ps1` 会：

- 用 MSVC 编译**全部平台无关 C++**（状态、授权、卡密、payload、目录、功能、反射兼容层、UI）
- 用 `tests/stub/` 顶替 mach/POSIX 头，用 `tests/platform_stubs.cpp` 顶替 ObjC 平台符号
- 链接成一个可执行文件，**把"声明了但没定义"的符号全部暴露出来**

当前结果：**全部通过**（`OK：全部目标文件编译并链接通过`）。

`ios/tests/crypto_test.cpp` 用公开测试向量验证 SHA-256 / HMAC / MD5 / RC4 / AES-256-GCM，
当前 **14/14 通过**。

这两项都不能替代 macOS 上的真机编译，但能挡掉绝大多数移植期的手误。
