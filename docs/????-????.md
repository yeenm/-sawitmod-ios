# 同行绘制（Peer ESP）— iOS 测试指引

> 只测这一个新功能，不要动其它开关（其它功能代码没改，行为应与上一版完全一致）。
> 本次 dylib：`dist-ios/SawitMod-v1.6.7-peerESP-iOS.dylib`（版本号仍是 v1.6.7，靠菜单里多出来的「绘制同行」区块区分）。

---

## 1. 装上去

| 方式 | 做法 |
|---|---|
| Sideloadly | `Advanced Options → +dylib/deb` 选中 `SawitMod-v1.6.7-peerESP-iOS.dylib`（和以前一样） |
| 已有注入包 | 把 IPA 解包里旧的 `SawitMod.dylib` **替换**成这个文件（文件名保持 `SawitMod.dylib`），重新签名 |
| TrollStore | 注入后的 IPA 直接装 |
| 越狱机 | 直接把 dylib 丢进 App 的 `Frameworks/` 并在二进制 Load 命令里加 `@executable_path/Frameworks/SawitMod.dylib`（沿用你原来的做法） |

> ⚠️ 如果旧版 dylib 已经在包里，**必须删掉旧的**再放新的，否则两个 dylib 同时注入会冲突。

## 2. 进游戏后的三步自检

### 2.1 看菜单有没有新区块

菜单 → 游戏 → 视觉 ESP 区域**上方**应出现：

```
绘制同行
[✓] 绘制同行（金色方框）   [立即同步]
名单 0 条 · 未同步 · 场景玩家 0 / 命中 0 · 我: -/-
```

- 勾选框默认 **开**（和安卓一致）；
- 状态行第三段 `我: 名片Id/shortId` 是关键：能显示出你的名片 Id（例如 `4s15w01`）说明符号解析成功。

### 2.2 点「立即同步」

正常应变成：

```
名单 3 条 · 3s 前同步 · 场景玩家 5 / 命中 1 · 我: 4s15w01/5135069185(月卡7FT7)
```

可能的失败提示（都是可读的，照着看就行）：

| 状态行 | 含义 / 处理 |
|---|---|
| `未登录卡密（名单同步需要卡密）` | 先过卡密登录（名单接口要卡密+设备码的 active session） |
| `报到失败：{"ok":false,"code":"NO_SESSION"}` | 面板里这张卡+这台机的 session 已失效，退出卡密重新登录一次 |
| `拉取名单失败：网络不可达` | 网络/代理问题，和卡密校验走同一个域名 |
| `名单 0 条` | 面板 `peer_uids` 表里还没有别的账号：让对方也登一次本模组（会 register） |

### 2.3 进世界后看「场景玩家」

- `场景玩家 0` → 实体表/GetAnyEntity 没通（这两个是硬依赖，看下一步符号自检）；
- `场景玩家 N` 但 `命中 0` → 名单里的人不在当前场景，或玩家 ID 符号没命中（状态行会带 `[注意] 玩家 ID 符号未命中`）。

## 3. 画面验收

| 场景 | 期望 |
|---|---|
| 名单里的号在你视野内 | 金色方框（四角加粗、框底一小段竖线）+ 上方 `称谓 [距离m]`，距离随走动变化 |
| 你自己 | **不被框**（三级自排除：netId / shortId / 名片 Id） |
| 背对/屏外 | 屏幕边缘出现金色三角箭头 + `称谓 距离m`，方向指向目标 |
| 两位同行 | 两个框；一前一后 = 一个框 + 一个箭头 |
| 关掉「绘制同行」 | 画面上立即没有同行元素；上面的雷达 ESP 行为不变 |

## 4. 出问题先点「符号自检」

菜单 → 其它 → 符号自检 → 等它跑完（进世界后约 2 秒）→ 报告写到 **App 的 Documents/SawitMod_symbols.txt**（用「文件」App 或 Filza 取）。

看这两节：

```
==== 同行绘制依赖符号（PeerEsp） ====
class XDTDataAndProtocol.ProtocolService.Player.PlayerProtocolManager => OK/NULL
    .TryGetPlayerShortId(i?) => OK/NULL   候选: ...
    .TryGetPlayerEncodeShortId(i?) => OK/NULL   候选: ...
class Sazabi.Login.Shared.ShortIdUtil => OK/NULL
    .DecodeShortId(s) => OK/NULL   候选: ...
class XDTLevelAndEntity.Core.World.Entity => OK/NULL
    .get_position() => OK/NULL
class XDTLevelAndEntity.BaseSystem.EntitiesManager.Entities => OK/NULL
    .GetAnyEntity(i) => OK/NULL

==== 同行绘制运行时状态（PeerEsp） ====
api.ready=1  proto=...  TryGetPlayerShortId=OK ...
selfNetId=...  selfUid=4s15w01  selfShortId=5135069185
peers=3  syncOk=2  syncFails=0  players=5  hits=1
note=已同步：名单 3 条
```

把这一整段（或整个 txt）发我，我就能判断是「符号名字对不上」还是「名单/会话问题」。
`候选:` 后面会把真实重载签名打出来——名字或参数对不上时，一行就能看出该改成什么。

## 5. 已知限制

1. 名单同步要求卡密会话有效（和安卓一致）；纯本地 `peer_tags.json` 兜底也要求先过卡密。
2. 本地兜底文件放这里（5 秒内生效，格式见 `docs/peer_tags.sample.json`）：
   `<Documents>/peer_tags.json` 或 `<Library/Application Support/SawitMod>/peer_tags.json`
3. 发布版 `SM_ENABLE_LOG=0`，没有控制台日志，全部信息看菜单状态行 / 符号自检报告。
4. 换场景后前几秒可能还没出框（每轮只识别 64 个新实体，属正常）。
5. 本版**未改** `SAWIT_VERSION`（v1.6.7），面板上版本号不会变。
