# 构建与注入

目标产物：`SawitMod.dylib`（arm64/arm64e），注入到**已解密**的心动小镇 iOS 包里。

---

## 1. 环境

| 工具 | 用途 | 备注 |
|---|---|---|
| macOS + Xcode | 编译（iOS SDK） | 版本 ≥ 14 |
| Theos | 构建 dylib | <https://theos.dev> |
| Dobby（源码） | inline hook | 需要自己编 iOS arm64 静态库 |
| `insert_dylib` | 给主二进制加 `LC_LOAD_DYLIB` | `brew install insert_dylib` 或 Tyilo/insert_dylib |
| `codesign` / `ldid` | 重签 | Xcode 自带 / `brew install ldid` |

```bash
export THEOS=~/theos
export PATH=$THEOS/bin:$PATH
```

## 2. 编译 Dobby

```bash
git clone --depth=1 https://github.com/jidongae/dobby.git
cd dobby

# 用 Xcode 的 iOS SDK 编 arm64 静态库
mkdir -p build-ios && cd build-ios
cmake .. \
  -DCMAKE_SYSTEM_NAME=iOS \
  -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=13.0 \
  -DCMAKE_BUILD_TYPE=Release \
  -DDOBBY_DEBUG=OFF \
  -DDOBBY_GENERATE_SHARED=OFF \
  -DCMAKE_INSTALL_PREFIX=install
make -j$(sysctl -n hw.ncpu)
make install
```

产出的 `libdobby.a` 放到：

```
ios/SawitMod/ThirdParty/Dobby/libdobby.a
```

> 也可以用 Theos 的 toolchain 直接编（把 `CMAKE_C_COMPILER/CMAKE_CXX_COMPILER` 指到
> `$THEOS/toolchain/.../clang`），效果一样。注意必须是 **arm64**，x86_64 的库链接会报架构不匹配。

## 3. 编译 dylib

```bash
cd ios
make clean
make            # 产物：.theos/obj/SawitMod.dylib
```

可选开关（与 Android 的 `ndk-build` 参数对应）：

```bash
make SAWIT_OFFLINE_MODE=0          # 关闭离线会话，强制走服务器卡密
make SAWIT_OFFLINE_MODE=1          # 默认：本地会话 + 内嵌功能目录
make DEBUG=1                       # 带调试符号（体积大，排错用）
```

`make` 会先检查 Dobby 是否存在，缺了会直接提示路径。

## 4. 注入 IPA

```bash
./scripts/inject_ipa.sh ~/xdt.ipa .theos/obj/SawitMod.dylib ~/xdt-mod.ipa
```

脚本做的事：

1. 解压 IPA → 找到 `Payload/*.app`
2. 拷贝 `SawitMod.dylib` 进 `.app`
3. `insert_dylib --strip-codesig --inplace @executable_path/SawitMod.dylib <主二进制>`
4. 重签 frameworks / dylib / 主 App（有 `embedded.mobileprovision` 时自动提取 entitlements）
5. 重新打包成 `xdt-mod.ipa`

**前置条件**：输入 IPA 必须是**已解密**的。App Store 下载的包是加密的（`cryptid=1`），
注入后无法运行。解密需要你自己的设备与工具，本仓库不提供。

## 5. 安装

| 方式 | 说明 |
|---|---|
| TrollStore | 不需要证书，直接装 `xdt-mod.ipa`；最省事 |
| AltStore / SideStore | 需要 Apple ID，7 天续签 |
| Sideloadly | 需要 ipa + 证书 |
| 越狱设备 | 也可以只把 dylib 拷到 `/usr/lib` 并让游戏加载（需配合 `DYLD_INSERT_LIBRARIES` 或 tweak 注入） |

## 6. Info.plist 必需项

放进 `Payload/XDT.app/Info.plist`（否则素材/导出功能不可用）：

```xml
<key>UIFileSharingEnabled</key><true/>
<key>LSSupportsOpeningDocumentsInPlace</key><true/>
```

可选：如果游戏本身没开网络，注入后仍能联网（授权/心跳走 `NSURLSession`），
ATS 对 HTTPS 默认放行；微验卡密的 80 端口走裸 socket，不受 ATS 影响。

## 7. 首次启动排错

| 现象 | 排查 |
|---|---|
| 启动即闪退 | 看 `~/Documents/mod_menu_crash_*.txt`；没有日志说明 dylib 没被加载（检查 `insert_dylib` 是否成功、签名是否有效） |
| 闪退在 `dyld: Library not loaded` | `@executable_path/SawitMod.dylib` 路径不对，或 dylib 架构不对 |
| 菜单不出现 | 看 Console.app 里 `[SawitMod] overlay started`；没有则 `SMOverlay::Start()` 失败（EAGLContext/窗口 scene） |
| 菜单出现但点不动 | 菜单矩形没更新（`DrawMenu` 没跑）或 `hitTest` 逻辑异常 |
| 功能列表空 | 离线构建没有内嵌目录：检查 `LocalCatalog::InstallEmbedded()` 是否被调用（日志 `State.cpp` 之后） |
| 帧泵功能不跑 | `OFF_GAMEAPP_UPDATE` 还是 0（未标定），日志会有 `跳过 GameApp.Update hook` |
| 卡密登录失败 | 检查设备时间（签名带 timestamp）、网络、以及 HWID 是否被服务端拉黑 |

打开日志：

```bash
# 编译时加 -DSM_ENABLE_LOG=1（Makefile 的 SAWIT_DEFINES），或用 Console.app 过滤 SawitMod
```

## 8. 标定偏移

见 `docs/移植说明.md` 第 4 节。核心流程：

1. IDA 打开 `UnityFramework`，按名字找到 `GameApp.Update`
2. 记 `函数地址 - 镜像基址` → 填 `Core/Offsets-iOS.h` 的 `OFF_GAMEAPP_UPDATE`
3. 重新 `make` + 注入
4. 启动日志出现 `GameApp.Update hook ok` 即成功

其他 `OFF_THEMIS_*` / `OFF_SDK_*` / `OFF_OVERLAP_*` 同理；不标定只是对应功能不生效，
不会导致崩溃（`Bootstrap` 对 0 偏移做了跳过）。

## 9. 本机自检（Windows 也能跑）

```powershell
cd ios
powershell -ExecutionPolicy Bypass -File scripts\check_link.ps1   # 编译+链接全部 C++（需要 VS Build Tools）
cl /nologo /utf-8 /std:c++17 /EHsc /I .\SawitMod\Core tests\crypto_test.cpp SawitMod\Core\Crypto.cpp
.\crypto_test.exe                                                 # 加密测试向量 14 项
```

`check_link.ps1` 通过 ≠ iOS 能编译（ObjC++ 与 UIKit 相关代码不在其中），
但它能挡掉跨模块漏实现、语法错误、类型不匹配这类问题。
