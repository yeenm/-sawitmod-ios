# iOS 同行绘制（Peer ESP）实现说明

> 对应安卓 `app/src/main/jni/PeerEsp.cpp`（v1.8.7 / v1.8.8 真机验证通过的那套）。
> 本文是 iOS 侧的落地说明：新增/改动文件、数据链路、符号依赖与兜底、参数、排障。
>
> 交接依据：`docs/同行绘制实现分析报告-交接iOS.md`（安卓侧实现分析）。
> 安卓侧功能行为规格（金色方框 / 称谓+距离 / 屏外箭头 / 300ms 刷新 / 双路匹配）
> 在 iOS 上**逐项对齐**，连颜色和尺寸常量都一样。

---

## 1. 一句话原理

```
服务端同行名单（uid 名片 Id / raw shortId）
        + 游戏内 netId →（TryGetPlayerShortId / TryGetPlayerEncodeShortId）→ id
        + netId → GetAnyEntity → get_position() → 世界坐标
        → Camera.WorldToScreenPoint → 屏幕坐标 → iOS 自己的 ImGui 悬浮层直接画金色方框
```

**关键点**：iOS 不需要 hook 游戏渲染。模组本来就有自己的 `UIWindow + CAEAGLLayer +
CADisplayLink` 悬浮层（菜单就画在里面），同行方框直接用同一个 ImGui 上下文画即可，
既不用碰 Unity 的 GL/Metal，也不会和原有雷达 ESP 打架。

## 3. 数据链路

```
┌──────────────────────────────┐
│ 自建面板 /api/peer/register  │ ← 卡密 + 设备码 + 名片 Id + raw shortId + platform=ios
│         /api/peer/list       │ → peers[]: {uid, label, role, shortId?, platform, ...}
└──────────┬───────────────────┘
           │ 后台线程，6s（首次）/10s（名单空）/30s（有名单）
┌──────────▼───────────────────┐
│ 名单层                        │  uid → label、shortId → label、本地 peer_tags.json 兜底
└──────────┬───────────────────┘
           │
┌──────────▼───────────────────┐   Unity 线程，300ms 一轮
│ 扫描层                        │   ① _netEntitiesMap 枚举 netId
│                               │   ② 每轮新实体探测预算 64：
│                               │      TryGetPlayerShortId / TryGetPlayerEncodeShortId
│                               │      （都拿不到时组件兜底判“是不是玩家”）
│                               │   ③ 双路匹配名单 + 取世界坐标
└──────────┬───────────────────┘
           │ 每帧
┌──────────▼───────────────────┐
│ 投影层                        │   WorldToScreenPoint + 背后 1-x/1-y 翻转
│                               │   + 相机直线距离（不是 screenPos.z！）
└──────────┬───────────────────┘
           │ 每帧（渲染线程）
┌──────────▼───────────────────┐
│ 绘制层                        │   ImGui 背景 drawList：金色方框 / 四角 / 脚下短线
│                               │   + 称谓[距离m] + 屏外贴边箭头
└──────────────────────────────┘
```

### 3.1 双路匹配（为什么不能只认 raw shortId）

云名单里有一半账号**只有名片 Id（uid）、没有 shortId**（PC 端报到或读不到 shortId）。
所以命中条件是：

```
命中 = 名单里有 raw shortId   或   名单里有 名片 Id(uid)
```

扫描期只要同一帧同时拿到 `(shortId, uid)`，就 `PeerEspRememberProfile()` 记下对应关系，
把 `uid → label` 回填成 `shortId → label`（反之亦然），避免下一轮漏人。
另外还支持用游戏自己的 `Sazabi.Login.Shared.ShortIdUtil.DecodeShortId(uid)` 把
名片 Id 反解成 raw shortId（拿不到 `TryGetPlayerShortId` 时的兜底）。

### 3.2 自排除

三级判据，任一命中即不画：

1. `netId == 自己 netId`（`GetSelfNetPlayerId` / `EntityUtil.GetSelfPlayer` 取，取不到就算 0）；
2. `raw shortId == 自己的 shortId`（`PlayerDataCenter._loginInfo.get_ShortId()`）；
3. `名片 Id == 自己的名片 Id`（`_loginInfo.get_GetEncodeShortId()`）。

**第 2/3 条不依赖 netId**，所以就算 iOS 某个版本读不到 `GetSelfNetPlayerId`，自己也不会被框。

## 4. 符号依赖与兜底（iOS 与安卓同版本应一致，但只在运行时才知道）

| 用途 | 类 | 成员 | 拿不到的后果 / 兜底 |
|---|---|---|---|
| 实体表 | `XDTDataAndProtocol.ComponentsData.DataCenter` | `get_CurrentData()` + `_netEntitiesMap` | 致命（没它什么都扫不到），与原有雷达同一套读取 |
| 实体对象 | `XDTLevelAndEntity.BaseSystem.EntitiesManager.Entities` | `GetAnyEntity(int)` | 致命 |
| 世界坐标 | `XDTLevelAndEntity.Core.World.Entity` | `get_position()` | 兜底：`NativeGetPosition()`（get_entity / transform / get_position 全试） |
| raw shortId | `…ProtocolService.Player.PlayerProtocolManager` | `TryGetPlayerShortId(uint, out long)` | 只靠 uid 匹配 |
| 名片 Id | 同上 | `TryGetPlayerEncodeShortId(uint, out string)` | 只靠 shortId 匹配 |
| 名片 Id → shortId | `Sazabi.Login.Shared.ShortIdUtil` | `DecodeShortId(string)` | 少一条桥接路径 |
| 判“是不是玩家” | `Entity.GetComponent<T>(bool)` + `BasePlayerComponent` / `RemotePlayerComponent` / `PlayerComponent` / `PlayerMorphComponent` / `ClientHideAndSeekHiderPlacedComponent` | 泛型膨胀 | 两个 Id 方法都 MISS 时才用（每轮最多 12 次，控制开销） |
| 自己 netId | `PlayerDataCenter.GetSelfNetPlayerId()` / `EntityUtil.GetSelfPlayer()` | — | 取不到也不致命（见 §3.2） |
| 相机 / 屏幕 | `UnityEngine.Camera.get_main` / `WorldToScreenPoint` / `Screen.get_width|height` | — | 与原有雷达共用 `ModUtils` 的实现 |

> `PlayerProtocolManager` 的命名空间按 5 个候选依次找（含 `""` 全镜像搜索），方法先用
> 「名字 + 参数签名 `i?`」精确解析，失败再退回「名字 + 参数个数 2」。

**真机自检**：菜单 → 其它 → 「符号自检」（`MonoSymbolProbe`）现在会多写两节
`==== 同行绘制依赖符号（PeerEsp） ====` 和 `==== 同行绘制运行时状态（PeerEsp） ====`，
报告写到 `Documents/SawitMod_symbols.txt`，能直接看出哪个符号 NULL、自己的
名片 Id/shortId 有没有读到、名单同步成功/失败次数。

## 5. 绘制规格（与安卓逐项一致）

| 项 | 数值 |
|---|---|
| 颜色 | 金色 `RGB(255,196,0)` |
| 方框 | 线宽 1.6，圆角 2.0；四角短线长 `w*0.28`、线宽 2.6；框底向下 8px 一小段竖线 |
| 框尺寸 | `h = clamp(2400/(distance+12), 46, 260)`，`w = h*0.46`；框底 = 屏幕点下方 6px |
| 标签 | 方框上方居中 `称谓 [距离m]`；深色底 `RGBA(0,0,0,120)` 圆角 3；文字 1px 黑描边 |
| 距离 | 相机到目标直线距离（相机坐标取 `Camera.transform.position`，取不到才退回 `screenPos.z`） |
| 屏外/背后 | 先 `1-x / 1-y` 翻转拿到方向，再沿「屏幕中心 → 目标」贴边（margin 42px），三角形 14px 尖 / 18px 底 + `称谓 距离m` |
| 刷新 | 实体扫描 300ms 一轮；投影+绘制每帧；名单同步 6/10/30s；自身身份 15s |

## 6. 使用步骤

1. 正常输入卡密登录（名单同步需要有效会话：`card + hwid` 必须能在面板查到 active session）。
2. 进游戏世界后打开菜单 → 视觉 ESP 区域上方的 **「绘制同行（金色方框）」**（默认开）。
3. 状态行示例：
   ```
   名单 3 条 · 12s 前同步 · 场景玩家 5 / 命中 1 · 我: 4s15w01/5135069185(月卡7FT7)
   ```
   - `名单 N 条`：服务端回下来的同行数量（含不在线的）；
   - `场景玩家 N / 命中 M`：本轮扫到多少个玩家、其中多少命中共用名单；
   - `我: 名片Id/shortId(卡等级)`：自己报到用的身份，方便和面板核对。
4. 点 **「立即同步」** 可立刻重发 register + list（换卡、刚进世界时用）。
5. 服务端不可用时，可把 `peer_tags.json` 放进 App 的 `Documents/`（或
   `Library/Application Support/SawitMod/`）：

   ```json
   {
     "tags": {"5135069185": "月卡7FT7", "80288948158": "月卡6YWD"},
     "uids": {"4s15w01": "月卡7FT7", "2arsg7xy": "月卡6YWD"}
   }
   ```

   `tags` 的 key 是 raw shortId（纯数字），`uids` 的 key 是名片 Id。

## 7. 与安卓的差异（都是有意的）

### 7.1 屏幕尺寸来源

安卓的 ESP 用 `glWidth/glHeight`（hook 时拿到的 EGL surface 尺寸）。iOS 侧这两个全局
**以前从未赋值（恒 0）**，所以原有雷达 ESP 的投影坐标其实全算成了 `(0,0)`。
本次在 `OverlayWindow.mm` 建 framebuffer 时顺手把它们设成 framebuffer 像素尺寸，
同行绘制自己也以 `g_RealScreenWidth/Height` 为基准，两边一致。

### 7.2 报到字段

`platform` 传 `"ios"`（面板会显示出来，便于排查）；`version` 仍是 `SAWIT_VERSION`。
面板 `/api/peer/*` 只校验 `card + hwid` 的会话，不校验 platform/version，所以三端互认。

### 7.3 本地兜底文件路径

iOS 沙盒没有 `/sdcard`，所以按顺序读：

```
<Documents>/peer_tags.json
<Library/Application Support/SawitMod>/peer_tags.json
<Documents>/peer_tags.txt
```

`Info.plist` 已有 `UIFileSharingEnabled` 的话，用户可以直接用「文件」App 放进去。

### 7.4 线程模型

- 名单 HTTP：后台 `std::thread`（**绝不在渲染/Unity 线程发请求**，这条和安卓一致）；
- 实体扫描 / 投影：走 `CADisplayLink → SMRunUnityFramePump()`，即 Unity 主线程；
- 绘制：同一帧的 ImGui `NewFrame()` 之后，纯 ImGui 调用，不碰 mono。

### 7.5 mono 调用

安卓是 `mono_*`（热更 Mono）；iOS 是 `_monoXxx` 指针，由 `IL2CPP/MonoHot` 路由到
UnityFramework 里真实的 `mono_*`。所以同一套 `FindClass / FindMethodBySignature /
_monoRuntimeInvoke` 写法两端通用，代码几乎可以逐行对照。

## 8. 排障（按这个顺序查最省时间）

| # | 症状 | 检查点 |
|---|---|---|
| 1 | 状态行一直「未登录卡密」 | 卡密没验证通过，`SesiAktif()` 为 false，名单不会同步（和安卓同样的门禁） |
| 2 | 状态行「已同步：名单 0 条」 | 服务端 `peer_uids` 表还没登记别人；让对方先登一次客户端（会 register） |
| 3 | 状态行「报到失败：{"ok":false,"code":"NO_SESSION"}」 | 面板里该卡密+设备码的 session 不是 active（重新登录一次） |
| 4 | 「名单 N 条」但「命中 0」 | 符号自检里看 `TryGetPlayerShortId` / `TryGetPlayerEncodeShortId` 是否 OK；若都 MISS，看 `BasePlayerComponent` 是否 OK（只靠组件判型时无法匹配 id → 需要补符号） |
| 5 | 「场景玩家 0」但游戏里明明有人 | `GetAnyEntity` / `_netEntitiesMap` 解析失败（符号自检里 `Entities` / `Entity` 那两行）；或还没进世界 |
| 6 | 有框但距离恒 0m | 相机坐标取不到（`Camera.transform.position`）→ 退回 `screenPos.z` 在屏外时 ≤0 |
| 7 | 转身后箭头方向反 | 说明 `WorldToScreenPoint().z <= 0` 的翻转没生效（相机/投影符号变了） |
| 8 | 自己也被框 | `_loginInfo` 读不到名片 Id/shortId，且 `GetSelfNetPlayerId` 也取不到（三级别排除全失效） |
| 9 | 菜单卡顿 | 调小 `kProbeBudgetPerScan`（默认 64）/ `kComponentProbeBudget`（默认 12） |
| 10 | 换场景后要等几秒才出框 | 正常：探测缓存里旧 netId 被清、新实体按每轮 64 个分批识别 |

## 10. 版本与面板注意

本次**没有改** `Version.h` 的 `SAWIT_VERSION`。原因：iOS 客户端登录时人为把
`platform` 传成 `"android"`（为了和安卓共用同一套签名），如果面板开了「版本门禁」
（`versionEnforced` + `versions` 白名单），改版本号可能直接被打回 `VERSION_UNSUPPORTED`。
要升版本号请先确认面板「设置 → 版本门禁」里的白名单/阈值再动。
